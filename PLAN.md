# Letter Burn — Plan (Stage 1)

**Goal:** Build a daily word game ("Letter Burn") where the player answers five prompts with words, and every distinct letter used burns out of their alphabet for the rest of the day. Finish all five while burning as few letters as possible.

**Repo:** letter-burn
**Launch date:** 2026-10-19 (Puzzle #1 is that date).
**Suggestion form URL:** blank for now (link hidden when empty per brief §3).

## Scope and constraints (from LETTER_BURN_BRIEF.md)
- React + TypeScript + Vite + Tailwind. Vitest for tests. No router — one page switching screens with state.
- localStorage for everything via `storage.ts` with a version number and migrations (game state, history, streak, tutorial seen, rejected words).
- Deploy to GitHub Pages via GitHub Actions; Vite `base` set from config (repo name).
- No AI or network calls at runtime. No accounts, leaderboards, backend, hints, power-ups, analytics, image share cards, sound (brief §12).
- Engine (`src/engine/`) is pure TypeScript with no React, so it's easy to test.
- Config lives in `src/config.ts`: name, tagline, URL, scoring weights (100 per prompt cleared, 5 per unburned letter, 8 per borrowed letter), borrow penalty, max borrows (3 per game), launch date 2026-10-19, suggestion form URL.
- Par is computed by the solver and shown only after the game ends, never during play.
- Practice puzzles are a separate set from daily puzzles; practice never spoils an upcoming day and never touches streaks/stats/history.
- `npm run build` fails if any scheduled daily puzzle fails the solver checks.

## Architecture
- `src/config.ts` — game config (name, tagline, URL, scoring weights, borrow penalty, max borrows, launch date, form URL).
- `src/data/` — `words.json`, `categories.json`, `puzzles.json`, `practice.json`.
- `src/engine/` — `normalize.ts`, `validate.ts`, `burn.ts`, `score.ts`, `daily.ts` (pure TS).
- `src/state/` — `useGame.ts`, `storage.ts`.
- `src/screens/` — `Home.tsx`, `Game.tsx`, `Results.tsx`, `History.tsx`, `HowTo.tsx`, `Practice.tsx`.
- `src/components/` — `AlphabetBank.tsx`, `LetterTile.tsx`, `PromptCard.tsx`, `AnswerInput.tsx`, `Preview.tsx`, `ShareButton.tsx`.
- `src/styles/` — `tokens.css`, `globals.css` (Tailwind tokens only from brief §9 palette; Big Shoulders Display + Instrument Sans via @fontsource).
- `scripts/` — `solve.ts` (check-puzzles, writes par), `apply-review.ts` (merge review decisions).
- `review/needs-review.csv` — borderline word/tag pairs for user review.

## Things in the brief I flag as risky / needing care
- **Answer coverage is the hard part:** 50–60 categories, 120+ accepted answers each, every word tagged with every honest category. The draft dictionary must be generated by me and borderline pairs sent to `review/needs-review.csv`; never guess into `words.json`.
- **Solver performance:** `scripts/solve.ts` must finish all 60 puzzles in under a minute with aggressive pruning (search zero-borrow sequences, each word clears ≥1 open prompt, shares no letters with earlier words).
- **Local midnight rollover:** puzzle for the player's local date; test with a mocked clock in two time zones.
- **Puzzle quality:** each daily needs ≥1 real Double Duty, zero-borrow solvable, ≥3 distinct solution routes, no single obvious best word for three prompts. Build 60 daily puzzles + 40 practice puzzles before launch.
- **Share text:** 26 squares A-Z in two rows of 13, no answers, no "Can you beat my score?" lines.
- **Mobile:** prompts + input + alphabet must fit without scrolling on 390×844 with keyboard closed; input + preview stay visible with keyboard open.

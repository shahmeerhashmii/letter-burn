# Letter Burn

A daily word game. Answer five everyday prompts, and every letter you use burns for the rest of the game. One clever word can clear two prompts at once.

Plain HTML, CSS and JavaScript. No build step, no npm, no server code. It runs as-is on GitHub Pages.

## Put it online (about 5 minutes)

1. Go to github.com, click **+** (top right), then **New repository**. Name it `letter-burn`, set it to **Public**, and click **Create repository**. Don't add a README.
2. On the new empty repo page, click the link **uploading an existing file**.
3. Unzip `letter-burn.zip` on your computer. Open the `letter-burn` folder, select **everything inside it** (the `css`, `data`, `fonts`, `js`, `tests`, `tools` and `word-bank` folders plus the loose files), and drag it all onto the GitHub upload page.
4. Wait for the uploads to finish, then click **Commit changes**.
5. Go to **Settings**, then **Pages** in the left menu. Under **Build and deployment**, set Source to **Deploy from a branch**, Branch to **main**, folder **/ (root)**, then click **Save**.
6. Wait a minute or two, then refresh that page. It shows your link, something like `https://yourname.github.io/letter-burn/`.

If you already uploaded Bob's version to this repo, delete the old files first, or make a fresh repo. It's easier.

## Testing before launch day

Puzzle #1 is set for **Monday, November 9, 2026**. Before then, the home screen offers practice rounds.

To try a real daily puzzle early, add `?date=` to the link:

- `.../letter-burn/?date=2026-11-12` plays as if it's Nov 12.
- `.../letter-burn/?date=2026-11-13` lets you check that the streak carries over.
- `.../letter-burn/?reset=1` wipes your saved progress on that device.

Progress is saved in each player's browser, so refreshing never loses a game.

## Changing things

| What | Where |
|---|---|
| Name, tagline, launch date, scoring, suggestion form link | `js/config.js` |
| Colours and look | `css/style.css` (colours are at the top) |
| Words and categories | `word-bank/letter-burn-word-bank.xlsx`, then rebuild (below) |
| Daily puzzles | `data/puzzles.json`, generated by the script below |

To upload an edited file later: open it on GitHub, click the pencil icon to edit, or use **Add file → Upload files** and upload it to the same folder. GitHub Pages updates itself within a minute or two.

### Suggestion form
Make a Google Form with one question ("Which word should count?"), copy its link, and paste it into `suggestFormUrl` in `js/config.js`. A "Think it should count?" link then shows whenever a word isn't recognised.

## Words and puzzles (needs Python on a computer)

You only need this when you change the word list, or when the puzzle schedule needs extending. Today there are 90 days scheduled (Nov 9, 2026 to Feb 6, 2027) plus 60 practice puzzles.

```
pip install openpyxl wordfreq
python3 tools/build_words.py      # Excel -> data/words.json + data/categories.json
python3 tools/make_puzzles.py --days 150   # adds days past the current end; published days never change
node tests/engine.test.mjs        # checks the rules and that every puzzle is solvable at par
```

Then upload the changed files in `data/`.

How puzzles are made: the script picks five categories that don't overlap too much (never "animal" together with "bird"), checks that at least one common word clears two of them, and solves the puzzle to find the best possible score ("par"). That solution only uses common, real words, with no initials like "BBQ" or "UK". It rejects puzzles that are too easy, too hard, or have fewer than 3 good routes. Par and one best route are shown to players after they finish.
